# 취향 성좌 개인정보·보존 정책 v1

## 데이터 분류와 기간

| 데이터 | 보존 기간 | 근거와 삭제 방식 |
| --- | --- | --- |
| 프로필, 아카이브, 개인 감상, Taste DNA | 사용자가 삭제할 때까지 | 서비스 핵심 기록. 작품별 삭제 또는 전체 삭제 제공 |
| 추천 연결 캐시 | 마지막 갱신 후 180일 | 재생성 가능하며 오래된 연결은 개인화 정확도를 낮춤 |
| 추천 좋아요·숨기기 반응 | 마지막 갱신 후 730일 | 장기 취향 신호에 필요하되 무기한 보관하지 않음 |
| 처리 완료 정보 신고 | 검수 후 365일 | 결과 문의와 검수 추적 기간 확보 |
| 미처리 정보 신고 | 생성 후 180일 | 장기 미처리 개인 제안 제거 |
| 처리된 메타데이터 변경 감사 | 최대 1,095일 | 개인 신고가 삭제되면 `report_id`를 분리해 공용 작품 변경 감사만 유지 |
| 복구 완료 중복 병합 감사 | 복구 후 최대 1,095일 | 카탈로그 복구의 책임성과 원인 추적 |
| 유효한 병합·작품 구분 예외 | 해결 또는 명시적 제거까지 | 잘못된 재병합을 막는 현재 카탈로그 무결성 상태 |
| 일반 상태 점검 | 90일 | 운영 추세 확인에 충분한 최소 기간 |
| 해결된 장애와 조치 | 해결 후 365일 | 재발 분석과 운영 책임 추적 |
| 분산 Rate Limit 버킷 | 마지막 요청 후 2일 | 원문 식별자나 IP가 아닌 SHA-256 버킷만 저장 |
| Cron 실행 기록 | 30일 | 자동 작업 장애 조사에 필요한 최소 기간 |
| 보존 정책 실행 집계 | 365일 | 개인 내용 없이 항목별 삭제 건수와 실행 시간만 보관 |

공용 작품 카탈로그와 출처·수상·대표 이미지 정보는 개인 데이터가 아니므로 이 자동 삭제 대상이 아니다.

## 사용자 전체 삭제

`delete_user_private_data(uuid)`는 프로필 한 행을 삭제하고 외래 키 연쇄 삭제로 아카이브, Taste 태그, 추천 연결, 추천 반응, 정보 신고를 하나의 트랜잭션에서 제거한다. 삭제 뒤 각 사용자 테이블에 잔여 행이 없는지 함수 내부에서 검사하며, 실패하면 전체 작업을 롤백한다. 처리된 신고에서 파생된 공용 작품 수정 이력은 신고 연결을 끊고 운영 감사 기록으로 유지될 수 있다.

Sites 로그인은 Supabase Auth 사용자가 아닌 안정적인 외부 식별자를 애플리케이션 프로필에 매핑한다. 따라서 전체 삭제는 Supabase Auth 계정 삭제가 아니라 이 서비스가 보유한 개인 취향 데이터 삭제를 의미한다.

## 자동 정리와 검증

- `run_data_retention()`은 한 테이블당 최대 5,000행만 잠금 충돌 없이 삭제한다.
- Supabase Cron이 매일 03:40 UTC에 실행한다.
- 실행 결과에는 개인 내용이 아니라 테이블별 삭제 건수, 정책 버전, 소요 시간만 기록한다.
- CI는 함수 권한, 보존 기간, Cron 일정과 개인정보 안내 문구가 소스와 일치하는지 검사한다.
- 정책 변경 시 마이그레이션, 이 문서, 사용자 개인정보 안내를 같은 배포에서 갱신한다.
